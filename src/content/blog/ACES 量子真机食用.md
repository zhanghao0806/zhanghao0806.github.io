## 一个简单的量子电路

### 写量子程序的框架

首先需要了解 **Qiskit、PennyLane** 这种框架，类比于深度学习中的 PyTorch/TensorFlow。这种框架封装了底层操作，让你搭线路、求梯度、连接量子后端等等更方便。

下面用的是 Qiskit。

### 量子线路的组成

主要有两大部分：量子线路本身怎么组成，线路怎么真正运行到QPU（或者模拟器）上。

第一部分：线路组成
$$
\text{Classical Input} \rightarrow \text{State Preparation / Data Encoding} \rightarrow \text{Parameterized Ansatz} \rightarrow \text{Measurement}
$$
**1 Classical Input 经典输入**

在进入量子线路前，此时是经典数据。对经典数据根据自己的要求，先进行预处理（比如归一化到某些角度方便后面做映射）。这一步是纯经典计算

**2 State Preparation / Data Encoding**

他们两不太一样，但是很多时候混在一起，后者可以看作是前者的一部分。

前者是状态制备（有很多叫法），硬件上所有的量子比特默认初始状态都是$|00\cdots0\rangle$，这一步就是把初始状态变成算法需要的量子态。

Data Encoding ：把经典信息注入量子态。这样讲有点抽象。我是这么理解的，经典数据我们用矩阵保存，矩阵每一个元素是数字，这些数字保存了信息。但是进入量子领域，信息就得用量子世界的格式保存：量子比特靠相位、概率振幅保存信息。所以数据编码其实就是把信息从一种格式（浮点数）映射到另一种格式（相位、概率振幅）。

那么这两个步骤有什么联系呢？比如：

把初态$|00\cdots0\rangle$ 制备到算法需要的状态$|\psi(\mathbf{x})\rangle$：
$$
|000\rangle \xrightarrow{H \quad CZ} |\psi_0\rangle \xrightarrow{R_y(x_1), R_y(x_2), R_y(x_3)} |\psi(\mathbf{x})\rangle
$$
上面过程第二段加的量子门，门的旋转角度是经典数据决定的，这些门就是Data Encoding 得到的。然后整个过程都属于State Preparation。

数据编码有角度编码、振幅编码等等很多方法。

**3 Parameterized Ansatz  参数化拟设** 

这一部分先把他叫做黑盒。制备的量子态，进入这个黑盒，得到最终的量子态。然后测量得到结果。

黑盒是一些量子门组成的，量子门包含可以训练的参数（量子门旋转角度）

（就像神经网络的参数一样）。（注意，Data Encoding 中量子门的角度是经典数据决定的，经典数据变，角度才会变。Ansatz 里面的角度，在训练过程中是不断变化的，优化器根据梯度更新。）

Ansatz 怎么设计方法很多：Hardware-efficient Ansatz、UCCSD、Adaptive Ansatz...

**4 Measurement**

测量。经过 Ansatz 之后得到需要的量子态，执行测量。真机给出的是 bitstring。

测量某个量子态，需要先选定基底。确定基底（泡利 Z矩阵）后，每一个量子态都可以表示成基底对应的本征态的线性组合。执行测量时，这个量子态会坍缩到某一个本征态。计算机对本征态做映射，态 0 读出 1；态 1 读出-1；

### 噪声指标

真机是有噪声的，一般是先在无噪条件下跑，然后用 Qiskit 的模拟器（比如 AerSimulator）建立噪声模型，做含噪模拟。最后在真机上跑。（这个项目有一部分是在本地含噪条件下训练到收敛，再上真机跑。其实就是预训练+微调）

一般需要知道硬件的以下指标：（标准定义自行了解）

**每个量子比特的 T1 、T2** 

T1 T2简单理解是量子比特存储信息的时间是有限的，超过这个时间，量子比特的信息就不准确了。所以电路深度不能设计太深，不然电路还没跑完，量子比特信息都丢失了，最终测量结果和理想线路的偏差会很大。

（我们三个比特 T1 分别是 45us/42us/40us ；T2 是 1.5us/1.9us/0.7us ；26 年一篇文章提到，世界上最好的超导量子比特记录 T2=1.5ms；领先了 3 个数量级）

**每个量子比特的读取保真度**

把 1 读成 1 、0 读成 0 的概率。

我们的三个比特读取保真度：0.85 / 0.82 / 0.81

**量子门的保真度**

单比特门：0.9984 / 0.9982 / 0.9983；

双比特门：0.98（Q1 和 Q2） 0.98（Q2 和 Q3）

世界最好记录：单 99.99%  双 99.9%

设计量子线路时，尽可能用真机保真度高的门。

**量子门执行时长**

门时长：单比特40ns，CZ60ns，RZ 0ns（VZ门）

先问 RZ 是否支持虚拟；

**真机友好的门**

真机有很多流派，不同硬件的原生门不一样。宁波真机是谷歌路线，此外还有 IBM 的传统路线等等。

* 宁波真机硬件友好门：RX，RZ，CZ；X，SX会更好。

  RZ 门尤其容易实现且RZ 可以虚拟；

  双比特门以 CZ 为主，并且不要加参数，把旋转角放在单比特门上；

  单比特门 RX RZ 支持任何角度，但是角度不要在 0 附近；在±二分之π或者π附近最好； 角度没有其他限制，可以小数。

  角度需要编译，真机支持两种实现方式，通过调脉冲实现，被分解为若干门（就是有几个门的组合，可以凑出任意角度；

  RZ 门尤其容易实现且RZ 可以虚拟；

设计量子线路，也最好用真机友好的门。

**量子比特的拓扑结构**

设计逻辑线路时，可以让任意两个比特产生纠缠，比如 Q1 和 Q9；但是生成在真机上执行的量子电路，需要让它满足拓扑约束：只有硬件上相邻的 qubit 才允许直接 CZ。

![拓扑图](/images/note/tuopu.png)

如图，Q69 和 Q76 挨着，可以直接加 CZ；但 Q69 没法和 Q78 直接 CZ。这个时候就要引入 SWAP 门，离得越远，SWAP 门越多。这是双比特门，带来的噪声副作用比单比特门大很多，当电路大量存在 SWAP ，电路效果不会好。

 所以最开始在设计阶段就应该满足拓扑约束，避免 Transpile 之后引入大量 SWAP 门。

**电路深度**

Transpile 之后的电路深度不能太深。

算法设计层面，你用了一些门，电路深度看着不深，但这只是 Logical circuit depth。Transpile 之后的 depth 才是真机要跑的深度。那为什么深度会变大？前面提到，逻辑门不一定等于真机原生门，电路先Transpile 成原生门之后才能在真机上跑，这个过程可能会引入 SWAP、routing 等等。

深度太大：电路执行时间变长，T1 T2 时间就那么点，最后结果偏差肯定大；门错误会累计，一个 CZ 的 0.999，看起来还不错。100个 CZ 就是 0.905；

**采样次数 shots**

这个不算噪声。一个 shot 是指初始化一次量子电路、执行一次门序列，得到一个 bitstring 的过程。shot 越多，统计误差越小。一般来说3000 就很够了。

## 得到电路图

先介绍一下三种对象

### QuantumCircuit、QPY、QASM

* **QuantumCircuit**：存在于内存中

  Qiskit 的 QuantumCircuit 类，是电路对象。简单说，Qiskit 会把你逻辑上设计的量子比特、门的顺序、连接规则什么的组装成 QuantumCircuit对象。可以根据这个对象画出电路图：

  ![](/images/note/base-quantum/2a3fdd31ff4c5a7684de3ef39f5dd880.png)

  但这个只是算法层面的，真机同学关心的是原生门组成的电路。

* **QPY**

  QPY是二进制文件，像是把 QuantumCircuit 原样打包保存；在 Qiskit 中完整存取这些电路，用 QPY；

  对 QuantumCircuit 对象 qpy.dump 之后可以得到 QPY 文件；

* **QASM**

  qasm 是人可读的 量子汇编语言。文本文件。描述了门、比特和测量等操作。方便在不同平台传递；

  对 QuantumCircuit 对象qasm3.dump 之后得到 QASM 文件；

### 下面展示怎么得到编译之后的电路图

* 先导入必要的包

  ```python
  from pathlib import Path
  from qiskit import qpy
  from qiskit import transpile
  ......
  ```

* 加载 由QuantumCircuit 生成的 QPY 文件

  ```python
  qpy_path = "logical_parameterized_circuits.qpy"
  with qpy_path.open("rb") as handle:
      circuits = qpy.load(handle) # Circuits是一个电路列表
  #这里有三个电路分别是：不带测量门、带测量门Z、带测量门 X
  state_preparation_circuit = circuits[0]
  z_measurement_circuit = circuits[1]
  x_measurement_circuit = circuits[2]
  ```

* 画出电路图

  ```python
  '''
  circuits[0].draw("mpl")
  得到上面的circuits[0]可以直接draw 出来，更好的是Transpile 成原生门再画;
  '''
  qc = transpile(
      circuits[0],
      basis_gates=["rx", "rz", "cz"],
      coupling_map=[[0, 1], [1, 0], [1, 2], [2, 1]],
      optimization_level=3,
      seed_transpiler=0,
  )
  qc.draw("mpl")
  ```

  ```circuits[0]```是待编译原始电路；

  ```basis_gates```就是真机的原生门，问负责硬件的同学；

  ```coupling_map```拓扑约束，表示Q0和Q1允许直接两比特门；Q1和 Q2 允许直接两比特门；如果 Q0 和 Q2 有纠缠，就要加入 SWAP 门；

  ```optimization_level```编译电路时的优化级别：4 档：0,1,2,3；级别越高，编译时间越久，但门数、电路深度和拓扑路由开销也会变少； 一般为了方便真机执行，opt 要开到 3；

  ![](/images/note/base-quantum/Transpile-after.png)

# 其他

## 指标

量子真机的噪声指标

**T1**：量子比特从态 1 变成态 0 的时间；经过时间 t，仍然保持在态 1 的概率为：
$$
P_1(t) = e^{-t/T_1}
$$
**T2**：混合态的相位信息能保持多久。

**相位**，会间接影响概率。

**所有处在混合态的量子比特，都携带相位信息**。但是这个相位信息不会影响基态的概率（所以说一个处在叠加态的量子比特相位信息发生改变是看不出来的）：$P_0 = |\alpha|^2$, $P_1 = |\beta|^2$
$$
|\psi\rangle = \alpha|0\rangle + \beta e^{i\phi}|1\rangle
$$
但是将它施加一个量子门（幺正变换），他计算基态的概率和相位有关了。
$$
H|\psi\rangle = \frac{1+e^{i\phi}}{2}|0\rangle + \frac{1-e^{i\phi}}{2}|1\rangle
$$
T1=30-40us, T2=3-4us 科创设备要求；

量子电路操作必须快：深度 乘以 门时间 必须 小于 T2 ；否则量子信息全部丢失，全是噪音信息。

## 量子门

H 门：Hadamard 门。单量子比特门。将基态变成均匀叠加态。

泡利 Z 门：不改变测量概率（振幅），只**改变相位**。对应布洛赫球绕 Z 轴旋转 180 度。

泡利 X 门：**翻转计算基态**。作用在叠加态上翻转两个计算基态的振幅。

泡利 Y 门：在 X 门效果基础上，增加了相位因子。三个泡利门都是绕对应坐标轴旋转 180°

以上门对应的幺正矩阵都是定值，不含参数。以下旋转门都带可训练参数/

RY 门：**参数化 ansatz 必备**；**最常用**。只改变计算基态的概率振幅。

RX 门：改变 0,1 占比，但会给 1 引入-i 的相位；

RZ 门：只改变相对相位，所以测量概率不会改变；

CZ 门：不含参数。主流**两比特**纠缠固定门。

## 特征编码

制备量子初态。**初始数据是向量**，变成量子态才能在电路上运行。

振幅编码有硬件制备难度，不是任意向量都容易造出来。

## 测量

### shots 采样

一个 shot 是指初始化一次量子电路、执行一次门序列，得到一个 bitstring 的过程。shot 越多，统计误差越小。

#### 一个具体的例子：

假设我要测量的泡利串是下面这些，采样数 shots=3000

```
ZII, IZI, IIZ, ZZI, ZIZ, IZZ, ZZZ,
XII, IXI, IIX, XXI, XIX
```

一个水分子构型，对应一个输入数据，跑一次程序。

这些泡利串，有 Z 基组，X 基组。

对于一个构型，原电路末尾直接测量，3000shots 采样，得到 8 种bitstring 出现的频率；

然后原电路后面加 H 门，再跑电路 3000 次，得到 8 种 bitstring 出现频率，这是 X 基测量结果；

所以，1 个构型，有 2 个测量电路，每条测量电路运行 3000 次，一共 6000 次。

## 在本地电脑写量子代码

**什么是量子后端？**  backend。 就是你设计的量子线路在什么设备上运行？类比经典网络，你的代码是在 CPU/GPU 运行？这就是后端。

### 角度编码的旋转角度是怎么交付的？每一个构型对应的角度都不一样

## 真机上参数更新过程

量子线路有 11 个可更新参数，当前 batchsize 设置为 2，一次加载 2 个构型，每个构型。

**原则：**更新 1 个参数，需要运行电路 3 次；保持当前所有参数不变，运行电路一次；该参数正移一点，运行电路；然后负移一点，运行电路，然后带入公式，计算这个参数的梯度；

误区：当前构型下，先运行 3 次电路计算梯度，更新该参数；再运行 3 次计算下一个参数的梯度；

不是的，当前构型，一次运行 23 （1+11x2）次电路，然后所有参数的梯度一次计算， 然后更新。

* 真机跑完一次拿到结果，更新 ansatz 参数之后；需要提交新的 ansatz 参数跑电路；这需要一个能访问 QPU 的经典电脑。形成一个循环。

## 量子经典混合模型怎么在真机上联合训练

因为有真机部分，也有经典部分。最终是这样的效果：
这边打包一份程序，最终在一台能访问 QPU 的电脑上 ，有这样一个训练脚本自动完成：对于每一个数据，脚本根据当前参数绑定并生成对应的量子线路，自动提交到真机，等待真机结果，然后本地电脑计算损失、量子参数的梯度（这里parameter-shift 需要额外提交参数扰动之后的 Circuit，再运行得到结果），更新量子参数。
然后脚本开始处理下一批数据，重复“绑定参数 → 提交 circuits → 获取测量结果 → 计算 loss/gradient → 更新参数”这个流程。

## 经典计算机和量子计算机

经典计算机怎么存储信息：晶体管和电容都是刻在**硅片上的电路**。用高低电平表示0,1。比如 DRAM 是电容充满电这个状态代表 1 ，反之代表 0；

超导量子计算机：量子比特也是在硅（当然也有其他）上的电路。量子计算机存储信息靠量子比特。但它存储的不是确定的0 态或者 1 态。（是叠加态），但每次读出量子比特，只会读出 0 或者 1。
