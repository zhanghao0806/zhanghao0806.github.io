**这篇论文干什么的？**

提出了一种新的方法，生成 Python 程序的调用图。

调用图：节点是函数，边表示谁可能调用谁；

重要条件是：在纯静态环境下（只看源码），把调用图画出来。

* 为什么不通过动态方法（运行代码）分析？

  1 运行程序有代价；

  2 而且覆盖不到所有的分支语句。所以静态条件下画调用图很有难度。更难的是 Python 是动态语言（不像 C++ Java 变量类型已经写死）。

# 基础知识

## Python AST

* Abstract Syntax Tree 抽象语法树；

  Python 代码执行前会被 Python 解释器 翻译成一系列中间产物，AST 是其中的一种。

* AST 有很多节点，节点算是 Python 对象吧，有很多**字段**。

  常见节点：FunctionDef（对应源码中的 def）、 Call （对应函数调用）、Assign（赋值语句）;

* 重要的函数 parse()，dump();

  Python的 dump() 很多类都有：大体作用都是把**内存中的某种数据“输出”，便于查看、保存**。

```Python
import  ast
code = "x = 1 + 2"
tree = ast.parse(code)
print(ast.dump(tree, indent=2))
```

## Pyhton 作用域机制

LEGB 原则；

函数是一等对象，可以**赋值给变量**，可以**作为函数参数**、可以**作为函数返回值**；但是注意不要带括号，只要函数名就行了;

```python
def test(func, arg):
    func(arg)
    func(arg)
test(print, "hello world")
'''
hello world
hello world
'''
```

## 论文如何将一个 Python 程序变成可分析的结构？Pipeline 是什么？

笼统两步：先得到赋值图，再得到调用图。

### Pipeline 

**1 源码变成中间表示：**

先把 python 代码变成解析成 AST；

但是 AST 还不够简洁，于是论文自定义了一种中间表示；

**2 维护 4 个核心状态域（数据结构）：**

得到中间表示之后，维护一些数据结构：作用域树、当前命名空间、赋值图；

作用域树，表示 谁 定义在 谁里面；

**3 不动点迭代分析（核心计算）：**

作者定义了状态转移规则：不断更新第二步的四个核心状态域；

最难理解的地方；

**4 生成调用图：**

第三步稳定后，生成了赋值图；这一步重新遍历中间表示，在赋值图的帮助下得到调用图。

论文定义一个算法流程。
