金融软件分析：PyCG论文复现

**这篇论文干什么的？**

提出了一种新的方法，生成 Python 程序的调用图。

调用图：节点是函数，边表示谁可能调用谁；

重要条件是：在纯静态环境下（只看源码），把调用图画出来。

* 为什么不通过动态方法（运行代码）分析？

  1 运行程序有代价；

  2 而且覆盖不到所有的分支语句。所以静态条件下画调用图很有难度。更难的是 Python 是动态语言（不像 C++ Java 变量类型已经写死）。

# 基础知识

## Python AST

* Abstract Syntax Tree 抽象语法树；

  Python 代码执行前会被 Python 解释器 翻译成一系列中间产物，AST 是其中的一种。

* AST 有很多节点，节点算是 Python 对象吧，有很多**字段**。

  常见节点：FunctionDef（对应源码中的 def）、 Call （对应函数调用）、Assign（赋值语句）;

* 重要的函数 parse()，dump();

  Python的 dump() 很多类都有：大体作用都是把**内存中的某种数据“输出”，便于查看、保存**。

```python
import  ast
code = "x = 1 + 2"
tree = ast.parse(code)
print(ast.dump(tree, indent=2))

'''
Module(
  body=[
    Assign(
      targets=[
        Name(id='x', ctx=Store())],
      value=BinOp(
        left=Constant(value=1),
        op=Add(),
        right=Constant(value=2)))],
  type_ignores=[])
'''
```

## Pyhton 作用域机制

LEGB 原则；

函数是一等对象，可以**赋值给变量**，可以**作为函数参数**、可以**作为函数返回值**；但是注意不要带括号，只要函数名就行了;

```python
def test(func, arg):
    func(arg)
    func(arg)
test(print, "hello world")
'''
hello world
hello world
'''
```

论文给出了 python 语言特性带来的挑战：现有静态方法没法解决这些问题。又举了现有两个开源静态分析器生成函数调用图的例子，显示他们的效果很差。 

关键设计：按照命名空间区分属性访问。





# 使用的方法

通过带上命名空间区分相同名字的字段；

图三：设计自己的语法结构，表示程序源码，相当于简化版的 AST；

## 论文如何将一个 Python 程序变成可分析的结构？Pipeline 是什么？

笼统两步：先得到赋值图，再得到调用图。

### Pipeline 

**1 源码变成中间表示：**

先把 python 代码变成解析成 AST；

但是 AST 还不够简洁，于是论文自定义了一种中间表示；

**2 维护 4 个核心状态域（数据结构）：**

得到中间表示之后，维护一些数据结构：作用域树、当前命名空间、赋值图；

作用域树，表示 谁 定义在 谁里面；

**3 不动点迭代分析（核心计算）：**

作者定义了状态转移规则：不断更新第二步的四个核心状态域直到收敛；

收敛：反复运用论文图六的状态转移规则，往作用域树、赋值图等添加新边，直到没有一条新边可以加。

最难理解的地方；

**4 生成调用图：**

第三步稳定后，生成了赋值图；这一步重新遍历中间表示，在赋值图的帮助下得到调用图。

论文定义一个算法流程。

## 样例源码

接下来以一个代表用例，详细介绍作者的程序是怎么生成调用图的。

关键：这个样例展示了：函数可以赋值给变量，函数还能作为形参传递，这些关系必须被追踪到。

parameters/nested_call：

```python
def nested_func():
    pass

def param_func(a):
    a()

def func(a):
    a(nested_func)

b = param_func
c = func
c(b)
```

* 重要区别：第八行，a(nested_func) 和 a(nested_func())。前者传进去的是函数本身，后者是**先执行函数**，然后传进去的是返回值。

  人写的话，这个调用图很简单。

## 第二步：

调用作者的PreProcessor，将 AST 变成作者的中间表示；

```python
import json

from pycg.pycg import CallGraphGenerator
from pycg.processing.preprocessor import PreProcessor
from pycg.utils.constants import CALL_GRAPH_OP, NAME_DEF

# 使用前面已经定义的 source_path
source_path = source_path.resolve()

# 创建分析器及其内部的数据管理对象
analyzer = CallGraphGenerator(
    entry_points=[str(source_path)],
    package=str(source_path.parent),
    max_iter=-1,
    operation=CALL_GRAPH_OP,
)

# 只运行预处理这一遍
try:
    analyzer.do_pass(
        PreProcessor,
        True,
        analyzer.import_manager,
        analyzer.scope_manager,
        analyzer.def_manager,
        analyzer.class_manager,
        analyzer.module_manager,
    )
finally:
    analyzer.remove_import_hooks()
```

运行完预处理，把数据打印出来看一下：

## 第三步：

传播关系直到收敛。

```python
from pycg.processing.postprocessor import PostProcessor

# 先补全预处理阶段记录的参数关系
analyzer.def_manager.complete_definitions()

# 重复分析，直到状态不再变化
while not analyzer.has_converged():
    analyzer.state = analyzer.extract_state()
    analyzer.reset_counters()

    analyzer.do_pass(
        PostProcessor,
        False,
        analyzer.import_manager,
        analyzer.scope_manager,
        analyzer.def_manager,
        analyzer.class_manager,
        analyzer.module_manager,
    )

    analyzer.def_manager.complete_definitions()

# 重新读取收敛后的信息，更新之前的 definitions
definitions = {}

for name, definition in analyzer.def_manager.get_defs().items():
    pointer = definition.get_name_pointer()
    definitions[name] = {
        "type": definition.get_type(),
        "points_to": sorted(pointer.get()),
        "arguments": {
            key: sorted(values)
            for key, values in pointer.get_args().items()
        },
    }

print("是否收敛：", analyzer.has_converged())
print(json.dumps(definitions, indent=2, ensure_ascii=False))
```

PyCG 的局限性：

### 不支持 * 号解包

assignments/starred

```python
def func1():
    pass
def func2():
    pass
def func3():
    pass
def func4():
    pass
a, *b, c = func1, func2, func3, func4
a()
b[0]()
b[1]()
c()
```

![](/images/experiment/NoSupport%2A.png)

不支持处理星号解包的“中间收集、尾部匹配”规则，导致函数绑定错误并遗漏调用边；

### 不支持内置对象的方法

builtins/types

```python
" ".join(["1", "2", "3"])
# 按空格拼接："1 2 3"
"a b c".split(" ")
# 按空格拆分： ["a", "b", "c"]
d = {"a": 1}
d.items()
# 可视化键值对
```

一共调用了三个函数，PyCG无法识别：不包含任何调用包。

评价指标：

精确率：分析器生成的边，有多少是正确的？
$$
\text{Precision} = \frac{|E_{\text{actual}} \cap E_{\text{expected}}|}{|E_{\text{actual}}|}
$$
召回率：真实的边，分析器找到了多少？
$$
\text{Recall} = \frac{|E_{\text{actual}} \cap E_{\text{expected}}|}{|E_{\text{expected}}|}
$$
